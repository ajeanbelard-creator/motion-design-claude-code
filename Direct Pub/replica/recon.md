# Carte de reconnaissance : Metricool (web)

Projet : **Direct Pub**, outil de gestion des réseaux sociaux inspiré de Metricool. Seules les
fonctionnalités et les parcours sont repris : code, textes, logos et visuels seront écrits ou
créés pour Direct Pub, avec un design minimaliste et épuré.

- **Périmètre** : toutes les fonctionnalités de l'application web, de A à Z (choix de
  l'utilisateur). Le tri entre ce qu'on garde, ce qu'on ajoute et ce qu'on retire se fera ensuite.
- **Plateforme** : application web (responsive). L'application mobile native est hors périmètre
  pour la première version.
- **Pour** : l'utilisateur, en produit propre (cible exacte à préciser avec `/replica-entrepreneur`).
- **Date** : 2026-11-23

## Règles suivies

- Sources publiques uniquement : site marketing, `llms.txt` et centre d'aide (lus page par page).
- Aucun compte Metricool utilisé, aucun code, bundle JS, endpoint privé ou capture réseau.
- Pas de captures d'écran prises : `replica/screens/` est vide. Si tu as un compte Metricool à
  toi, quelques captures de référence aideront `/replica-design` (elles ne seront jamais livrées).

## Boucle centrale

**Connecter les comptes d'une marque, planifier et publier automatiquement sur tous les réseaux
depuis un seul calendrier, puis mesurer les résultats.** Tout le reste (messagerie, rapports,
pubs, validation) s'ajoute autour.

## Organisation

```
Compte (login, e-mail, préférences)
 └─ Organisation (propriétaire + équipe, facturation)
     └─ Marques (1 client / 1 entreprise)
         └─ Profils sociaux (1 par réseau et par marque) + 1 site web + comptes pub
```

Réseaux : Facebook, Instagram, Threads, X, Bluesky, LinkedIn (page ou profil), Pinterest,
TikTok, YouTube, Google Business Profile, Twitch, site web / blog. Pubs : Meta Ads,
Google Ads, TikTok Ads.

Navigation : barre du haut avec 6 blocs (**Planification, Analytique, Messagerie, Rapports,
SmartLinks, Pubs**), sélecteur de marque, menu ☰ (connexions, réglages de marque, utilisateurs,
organisation, abonnement, demandes de validation, langue, réglages du compte, nouveautés, aide).

## Parcours

```
F01 Créer son compte et sa première marque
    S01 -> S02 -> S03
    clics (chemin heureux) : ~6
    cas limites : e-mail non confirmé, réseau refusé à l'OAuth, mauvais compte connecté

F02 Connecter un réseau social
    S03 -> OAuth du réseau -> S03 (connecté)
    clics : 3
    cas limites : jeton expiré, permissions manquantes, compte Instagram non professionnel,
    lien de connexion envoyé au client sans compte

F03 Créer et planifier un post multi-réseaux
    S06 -> S08 (texte, médias, réseaux, adaptation par réseau, date) -> Planifier -> S06
    clics : ~7
    cas limites : limite de caractères dépassée, format de média refusé, date passée,
    publication échouée (statut « avec erreurs »), publication manuelle par notification

F04 Replanifier par glisser-déposer
    S06 (glisser un post en attente vers un autre créneau)
    clics : 1
    cas limites : post publié (interdit), date passée, post issu d'une autoliste

F05 Choisir le meilleur horaire
    S06 -> S22 (carte de chaleur) -> S08 (créneau choisi)
    cas limites : moins de 100 abonnés -> horaires génériques

F06 Garder une idée pour plus tard
    S08 -> « Envoyer à la bibliothèque » -> S10 -> déplacer la carte de colonne -> « Créer le post » -> date
    cas limites : limite de 250, post déjà planifié (doit être dupliqué)

F07 Publier en continu avec une autoliste
    S11 -> nouvelle autoliste -> réseaux -> créneaux hebdomadaires -> contenu (manuel, IA, CSV, RSS) -> activer
    cas limites : 200 posts max, liste vide, post en pause, mode répétition

F08 Planifier en masse par CSV
    S06 -> S12 -> télécharger le modèle -> importer -> vérifier -> S06
    cas limites : mauvais format de date, lien média non public, encodage non UTF-8

F09 Programmer une récurrence
    S08 -> ▾ Planifier -> S09 -> aperçu -> planifier
    cas limites : plus de 180 jours, plus de 200 posts, consigne en texte libre ambiguë

F10 Faire valider un post
    S08 -> « Envoyer en validation » -> relecteurs + critère -> S06 (statut en attente)
    -> relecteur : S15 ou S16 -> approuver / refuser (+ note)
    cas limites : post modifié après envoi (validation remise à zéro), refus d'un seul relecteur,
    délai de grâce de 3 h dépassé

F11 Répondre à un message
    S28 -> filtrer -> ouvrir la conversation -> réponse (ou réponse enregistrée) -> marquer résolu
    clics : ~4
    cas limites : fenêtre de réponse DM de 7 jours dépassée, réseau qui n'autorise pas la réponse

F12 Lire ses statistiques
    S17 -> choisir la période -> S18 (réseau) -> trier la liste des posts -> S20
    cas limites : section vide masquée, comparaison impossible (historique trop court)

F13 Se comparer aux concurrents
    S21 -> ajouter un concurrent (pseudo) -> tableau -> posts du concurrent
    cas limites : réseau non pris en charge, compte privé

F14 Produire un rapport client
    S23 -> période, réseaux, logo, modèle -> PDF / PPT -> envoi mensuel automatique
    cas limites : génération longue, rapport supprimé mais lien déjà partagé

F15 Suivre une campagne
    S25 -> nom, dates, objectifs -> contenus suggérés -> synchroniser -> lien public
    cas limites : plus de 180 jours, contenus de plusieurs marques (interdit)

F16 Publier un lien en bio
    S29 -> créer -> boutons / design -> copier l'URL -> S30 -> statistiques
    cas limites : URL déjà prise

F17 Inviter quelqu'un
    S34 -> membre d'équipe (toutes les marques) ou collaborateur (marques choisies) -> rôle -> e-mail
    cas limites : invitation expirée après 24 h, rôle sans permission de marque pour un collaborateur

F18 Piloter les pubs
    S31 -> mettre en pause / changer le budget ; S32 -> créer -> code de confirmation par e-mail
    cas limites : compte pub non connecté, campagne TikTok (lecture seule)

F19 Automatiser une réponse (Flow)
    S14 -> modèle (ex. commentaire avec mot-clé -> DM) -> mots-clés -> message -> activer
    cas limites : compte non professionnel, quota d'exécutions atteint
```

## Hors périmètre (impossible ou à ne pas copier)

- **Le nom, le logo, les textes, les illustrations, les captures et le code de Metricool.**
  Direct Pub a sa propre identité (`/replica-brand`).
- **Les études de comportement** qui donnent les « meilleurs horaires génériques » : ce sont des
  données propriétaires. Direct Pub calculera ses horaires à partir des statistiques du compte,
  ou partira d'une grille neutre.
- **La bibliothèque musicale** (musiques tendance TikTok, audio Instagram) : contenu sous
  licence, réservé aux partenaires des réseaux.
- **La banque d'images, vidéos et GIF intégrée** : contenu sous licence. Remplaçable par une API
  officielle (ex. Unsplash, Pexels, Giphy) avec leurs conditions.
- **L'historique stocké par d'autres utilisateurs** (concurrents, comptes déjà suivis) : c'est la
  base de données de Metricool.
- **L'accès aux API des réseaux** n'est pas copiable : il faut demander le tien. Meta (Facebook,
  Instagram, Threads), TikTok, LinkedIn, Google et Pinterest imposent une validation de
  l'application ; l'API X est payante ; LinkedIn réserve certaines API à ses partenaires.
- **Le programme d'affiliation, la marque blanche, l'application mobile native, le connecteur
  Looker Studio et le serveur MCP** : possibles plus tard, mais hors de la première version.
- **L'assistance par chat et la resynchronisation manuelle d'historique** : c'est un service,
  pas une fonctionnalité.

## Taille

- **Écrans** : 39. **Parcours** : 19. **Entités** : ~45.
- **Parties difficiles** :
  1. **Les intégrations de 12 réseaux et 3 régies pub** : OAuth, renouvellement des jetons,
     formats et limites propres à chacun, validation des applications par chaque réseau
     (des semaines, hors de notre contrôle).
  2. **La publication fiable à l'heure** : file de tâches, reprises, envoi des médias (vidéo
     lourde, conversion), statuts et alertes d'échec, fuseaux horaires.
  3. **La collecte quotidienne des statistiques** : synchronisation par réseau, quotas d'API,
     historique, calculs (engagement, comparaisons de périodes), puis rapports PDF / PPT.
  Ensuite : la messagerie unifiée (webhooks par réseau), la validation, les fonctions IA.
- **Taille : XL.** Tout Metricool de A à Z, c'est plusieurs trimestres. Il faut découper en
  versions :
  - **V1 (M, quelques semaines)** : les lignes `must`, avec 3 ou 4 réseaux (par exemple
    Instagram, Facebook, LinkedIn, Bluesky ; Bluesky n'a pas de validation d'application et
    permet de tester tout de suite).
  - **V2 (L)** : les lignes `should` : réseaux restants, messagerie, validation, rapports,
    bibliothèque, autolistes, concurrents.
  - **V3** : les lignes `could` : pubs, Flows, Studio IA, tableaux de campagne, hashtags.
